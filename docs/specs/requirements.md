# 需求规格说明书（Requirements Specification）

- **项目名称**：TranslationAssistant（AI 高保真文档翻译助手）
- **文档版本**：v2.0（纯 Go 自研 PDF 引擎 + 全栈商业友好开源协议版）
- **适用范围**：Phase 1（PDF 保真翻译与 Web 工作台 MVP）及 Phase 2/3 演进规划

---

## 1. 项目背景与核心原则

### 1.1 业务痛点
现有 PDF 翻译工具普遍存在四类问题：
1. **排版破坏**：复制粘贴或粗暴转 Word 容易导致多栏错乱、表格崩溃、图文分离。
2. **黑盒不可编辑**：命令行工具翻译完直接输出 PDF，译文生硬或长度溢出时无法在网页端所见即所得微调。
3. **长文档等待久**：必须整本翻完才能查看，缺少实时流式预览与断点续译。
4. **隐私与授权受限**：商业 SaaS 昂贵且文档需上传第三方；主流开源 PDF 引擎（如 MuPDF / PyMuPDF、UniPDF）均采用 **AGPLv3 或商业收费授权**，存在闭源商用合规风险。

### 1.2 核心架构原则
1. **核心 PDF 引擎自主可控**：后端采用 **纯 Go 语言完整自研** PDF 结构解析、指令级无损擦除、中文字体嵌入与保真排版回填框架（`pdfengine`），零 CGo、零 Python 运行时依赖。
2. **全栈商业友好协议（Zero AGPL / Zero Commercial Lock-in）**：项目引入的所有第三方库、框架与内置字体必须严格限定在 **MIT / Apache-2.0 / BSD-3-Clause / ISC / SIL OFL-1.1** 等允许自由闭源商用的开源协议范围内。
3. **本地优先与高可扩展**：零外部中间件（单二进制 + SQLite + 本地文件目录），底层通过统一文档中间表示（Document IR）为未来扩展 DOCX / PPTX / Markdown / OCR 预留接口。

## 2. 需要您提前确认的自研边界与功能取舍

> [!WARNING]
> 为彻底避开 AGPL/商业授权库并保持合理的研发周期，纯 Go 自研路线在首期（v1）存在以下 **4 项明确的功能边界与取舍**，请您审阅确认：
>
> 1. **首页缩略图由前端生成（后端不自研光栅化渲染器）**
>    - *原因*：PDF 光栅化（矢量抗锯齿、CMYK、JBIG2/JPEG2000 图像解码）占传统引擎 80% 代码量，而前端浏览器已有 Apache-2.0 协议的 `PDF.js`。
>    - *方案*：后端专注 PDF 结构解析与指令级编辑；文档首页缩略图由前端 `PDF.js` 在上传/首次打开时渲染并回传缓存。**无核心功能损失**。
> 2. **v1 支持标准未加密电子版 PDF（1.4 ~ 2.0），暂不支持加密/严重损坏 PDF 及扫描件 OCR**
>    - *覆盖范围*：完整支持 Word、LaTeX、Chrome、macOS 预览、Adobe 等导出的标准电子版 PDF（涵盖 `FlateDecode`、`ASCII85`、`Object Streams`、`XRef Streams`、`Form XObject`、`Type1`/`TrueType`/`Type0 CIDFont` 与 `ToUnicode CMap`）。
>    - *功能边界*：遇到密码加密 PDF 或无文本层的纯图片扫描 PDF，系统检测并给出明确中文提示；遇到缺失 `ToUnicode` 映射的特殊数学符号字体，自动标记跳过保护不破坏原公式。长尾异常 PDF 通过后续测试用例持续迭代补齐。
> 3. **中文字体子集化（TTF Subsetter）分两步落地**
>    - *原因*：TrueType 二进制子集裁剪（重写 `glyf`/`loca`/`cmap`/`hmtx` 等十余张表及校验和）容错率极低。
>    - *建议策略*：**M2a** 先跑通标准 CIDFont 中文字体嵌入（配合 Flate 压缩，确保 100% 兼容各 PDF 阅读器、导出文件增加约 4~6MB）；紧接着在 **M2b** 交付自研 TrueType 子集裁剪器，将字体增量压降至 200~500KB。*(请确认是否同意此稳健分步策略，或希望在 M2 一步到位死磕子集裁剪)*。
> 4. **专注横排保真原位回填，暂不支持竖排文字与自动跨页重排**
>    - *边界*：支持单栏/双栏/多栏横排文档的原位自适应缩放重绘；不支持古籍/日文竖排文字重绘，也不改变原文档总页数（溢出时通过字号自动微调 + Web 端拖拽拉框/AI 精简解决）。

## 4. 功能需求与验收标准（Functional Requirements）

> 优先级：**P0（MVP 必做）**、**P1（Phase 2 增强）**、**P2（Phase 3 远期扩展）**。验收标准采用 **EARS** 规范编写。

### REQ-01：文档上传、管理与持久化（P0）
**用户故事**：作为用户，我希望能在 Web 端上传 PDF 并管理历史翻译项目，以便随时中断并在之后继续校对和导出。
- **AC-1.1**：`WHEN` 用户拖拽或选择 `.pdf` 文件上传时，`THE SYSTEM SHALL` 校验文件魔数（`%PDF-`）、后缀及大小（默认上限 100MB），通过后持久化原文件并创建文档记录。
- **AC-1.2**：`WHEN` 用户上传非 PDF、损坏文件或超限文件时，`THE SYSTEM SHALL` 拒绝上传并返回明确中文错误提示。
- **AC-1.3**：`WHEN` 用户查看首页文档库时，`THE SYSTEM SHALL` 展示历史文档列表（含文件名、页数、翻译进度百分比、状态标签、更新时间及缩略图）。
- **AC-1.4**：`WHEN` 用户确认删除文档时，`THE SYSTEM SHALL` 同步删除数据库记录及磁盘关联的所有文件（原 PDF、纯净底图 PDF、缩略图、导出缓存）。

### REQ-02：纯 Go 自研 PDF 智能解析与无损底图生成（P0）
**用户故事**：作为用户，我希望上传 PDF 后系统能自动理解版面结构（段落、双栏、字体、坐标），并保留所有图片、表格线和背景不被破坏。
- **AC-2.1**：`WHEN` PDF 上传完成后，`THE SYSTEM SHALL` 使用自研 `pdfengine` 异步解析每页尺寸、所有文本块坐标（`bbox`）、原文、字号、字重、颜色、对齐方式，生成 Document IR 存入 SQLite。
- **AC-2.2**：`WHEN` 同段落文字在 PDF 中被拆分为多行或碎片 span 时，`THE SYSTEM SHALL` 基于几何间距与样式一致性自动合并为完整段落，并处理英文行尾连字符断词。
- **AC-2.3**：`WHEN` 页面为双栏排版时，`THE SYSTEM SHALL` 自动检测分栏空白槽并按“跨栏标题 -> 左栏自上而下 -> 右栏自上而下”的正确顺序编号。
- **AC-2.4**：`WHEN` 文本块为纯页码、纯数字编号、纯 URL 或缺失 `ToUnicode` 的数学符号字体片段时，`THE SYSTEM SHALL` 自动标记 `translatable = false`（原样保留不擦除）。
- **AC-2.5**：`WHEN` 版面解析完成时，`THE SYSTEM SHALL` 通过自研 `redactor` 生成一份指令级擦除可译文字的纯净底图 PDF（`clean_bg.pdf`），100% 保留原文档的位图图片、矢量线条、表格边框与渐变背景，供 Web 端译文画布无损预览。
- **AC-2.6**：`IF` 检测到密码加密 PDF 或无有效文本层的纯扫描版 PDF，`THE SYSTEM SHALL` 标记对应状态并在前端明确提示原因，不崩溃也不产生空白脏数据。

### REQ-03：AI 模型服务商管理与配置（P0）
**用户故事**：作为用户，我希望在 Web 界面自由配置多个 OpenAI 兼容模型（OpenAI / DeepSeek / Gemini / 通义千问 / 本地 Ollama）并测试连通性。
- **AC-3.1**：`WHEN` 用户打开模型设置弹窗时，`THE SYSTEM SHALL` 支持增删改模型预设与设置默认模型（含名称、Base URL、API Key、Model ID、最大并发数、温度）。
- **AC-3.2**：`WHEN` 用户点击“测试连接”时，`THE SYSTEM SHALL` 发送最小化探针并在 10 秒内反馈成功（含耗时 ms）或具体失败原因。
- **AC-3.3**：`WHEN` 后端返回模型配置列表时，`THE SYSTEM SHALL` 对 API Key 进行掩码脱敏，绝不回传完整明文。

### REQ-04：上下文感知的流式并发翻译（P0）
**用户故事**：作为用户，我希望一键启动翻译并边翻边看，支持随时暂停、断点续译和失败块重试。
- **AC-4.1**：`WHEN` 用户选择语言与翻译风格（通用/学术/技术/商务）并点击“开始翻译”时，`THE SYSTEM SHALL` 启动 Go 并发调度器（基于 Goroutine Pool 限流），按页动态打包结构化 JSON 请求并透传前文摘要。
- **AC-4.2**：`WHILE` 翻译运行期间，`THE SYSTEM SHALL` 通过 SSE 实时推送每块完成事件，前端译文画布即时呈现译文。
- **AC-4.3**：`WHEN` 单批次因网络抖动或 429 限流失败时，`THE SYSTEM SHALL` 执行最多 3 次指数退避重试；若仍失败仅标记受影响块为 `failed` 并继续其余页面。
- **AC-4.4**：`WHEN` 用户点击“暂停”后再次点击“继续”时，`THE SYSTEM SHALL` 保留已译结果并仅对剩余 `pending`/`failed` 块断点续译。

### REQ-05：Web 端多视图保真预览（P0）
**用户故事**：作为用户，我希望在浏览器中以多种视图高清预览原版与保真译文，并实现双栏同步对照。
- **AC-5.1**：`WHEN` 用户进入工作台时，`THE SYSTEM SHALL` 支持即时切换三种视图：**双栏对照视图（左原右译）**、**纯译文视图**、**CAT 段落校对列表视图**。
- **AC-5.2**：`WHILE` 处于双栏对照视图时，`THE SYSTEM SHALL` 左侧渲染 `original.pdf`、右侧渲染 `clean_bg.pdf` + 透明可编辑译文层，保持左右缩放一致与双向同步滚动。
- **AC-5.3**：`WHEN` 用户悬停或点击任一侧文本块时，`THE SYSTEM SHALL` 双栏双向高亮对应区块，并在右侧检查器展示详情。
- **AC-5.4**：`WHEN` 文档超过 20 页时，`THE SYSTEM SHALL` 采用按需视口懒加载渲染 PDF.js 页面并提供左侧缩略图/页码快速跳转。

### REQ-06：Web 端所见即所得在线编辑与校对（P0）
**用户故事**：作为用户，我希望直接在保真页面上修改译文、微调字号与文本框大小，并能对单段调用 AI 局部润色。
- **AC-6.1**：`WHEN` 用户双击画布文本块或在右侧检查器修改译文时，`THE SYSTEM SHALL` 实时更新渲染并在 800ms 后自动防抖保存至后端，块状态变更为 `edited`。
- **AC-6.2**：`WHEN` 用户调整字号、行高、对齐、颜色或拖拽微调文本框位置/尺寸时，`THE SYSTEM SHALL` 实时生效并持久化，导出 PDF 严格还原该微调。
- **AC-6.3**：`WHEN` 译文在 `bbox` 内视觉溢出时，`THE SYSTEM SHALL` 自动温和缩减显示字号（下限为原字号 65%）；若仍溢出则高亮“文本溢出”提示图标。
- **AC-6.4**：`WHEN` 用户在检查器点击“AI 局部重译 / 润色”（含“更学术”“精简以适配宽度”或自定义指令）时，`THE SYSTEM SHALL` 仅对该块重新生成译文供用户一键采纳。
- **AC-6.5**：`WHILE` 在工作台编辑时，`THE SYSTEM SHALL` 支持 `Cmd/Ctrl + Z` 撤销与 `Cmd/Ctrl + Shift + Z` 重做（至少 30 步）。
- **AC-6.6**：`WHILE` 处于 CAT 段落列表视图时，`THE SYSTEM SHALL` 支持关键词搜索、状态筛选与一键标记“已审校（reviewed）”。

### REQ-07：高保真 PDF 导出（P0）
**用户故事**：作为用户，我希望校对完成后能一键导出保持原有排版、图文完整的纯译文 PDF 或双语对照 PDF。
- **AC-7.1**：`WHEN` 用户导出“纯译文保真 PDF”时，`THE SYSTEM SHALL` 通过自研 `pdfengine` 在 `clean_bg.pdf` 基础上，利用内置开源中文字体（Noto Sans SC）和自适应折行排版引擎重绘所有译文，100% 保留底层位图与矢量线条。
- **AC-7.2**：`WHEN` 用户导出“双语对照 PDF”时，`THE SYSTEM SHALL` 支持 **交替页模式（奇原偶译）** 与 **左右并排拼接模式**。
- **AC-7.3**：`WHEN` 导出 PDF 包含中英文混排时，`THE SYSTEM SHALL` 确保在 macOS 预览、Chrome、Adobe Acrobat 中均无乱码、无字形缺失且支持文本复制检索（含正确 `ToUnicode` 表）。

### REQ-08：演进扩展需求（P1 / P2，架构预留）
- **REQ-08.1（P1）**：术语库（Glossary）管理与翻译 Prompt 自动注入。
- **REQ-08.2（P1）**：扫描版 PDF 接入合规 OCR（Apache-2.0 的 PaddleOCR 或多模态大模型 VLM API）。
- **REQ-08.3（P2）**：纯 Go 自研 OOXML 适配器，支持 `.docx` / `.pptx` / `.md` / `.epub` 保真翻译。
- **REQ-08.4（P2）**：翻译记忆库（TM）自动沉淀与相似句段复用。

## 5. 非功能需求（NFR）

| 类别 | 指标与要求 |
| :--- | :--- |
| **开源协议合规** | 100% 依赖均为 MIT / Apache-2.0 / BSD / ISC / SIL OFL-1.1；**严禁引入 GPL / AGPL / 商业收费库**。 |
| **部署形态** | 后端单 Go 二进制（零 CGo、零 Python 依赖），支持 macOS / Linux / Windows 交叉编译，内置 SQLite 零外部数据库。 |
| **解析与导出性能** | 20 页标准文本 PDF 解析 + 生成 `clean_bg.pdf` 时间 ≤ 3 秒；导出保真 PDF ≤ 3 秒。 |
| **保真度指标** | 原 PDF 位图图片与矢量路径保留率 100%；文本块视觉坐标对齐误差 ≤ 2pt。 |
| **可靠性与安全** | 任一页面/批次异常不导致服务崩溃；API Key 脱敏返回；上传路径防穿越校验。 |
